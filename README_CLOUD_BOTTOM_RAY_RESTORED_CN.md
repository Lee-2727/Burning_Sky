# V2.2.0：恢复云底 + 云锋面双受光几何（2026-11-18）

## 修改范围

- `burning_sky/sky_six.py`：严格球面验证新增 **每目标云块 5 个水平云底采样条带**。每一条独立按相应位置的太阳高度角、实际云层交集及地球曲率验算。旧云锋面光路保留但不再代替云底受光。
- `burning_sky/local_cloud_illumination.py`：正式可染色云占比以已验证的云底受光条带为主；**云锋面另外单独输出诊断**，不再用前缘的垂直高度比冒充整片云底面积。无法覆盖的离轴光路作为未确认区间输出，不按晴空假定。
- `engine.py`：主光路门槛接受有效云底光路；输出分列说明云底可染色占比、云锋面受光比例和不足以验证的条带。保留概率与规模独立的原设定。
- `burning_sky/profile_image.py`、`desktop/spatial_v2_visual.py` 和 `engine.py` 的桌面剖面视图：已验证的云底光路从真实云底受光点绘制，旧的前缘候选仍为虚线。
- `tests/test_bottom_surface_restoration.py`：独立测试云底自交、上游云墙、球面地平线、目标门控及离轴缺失处理。`tests/test_upstream_700_gate.py` 同步取消旧版无物理依据的固定 20 km 终点门槛断言，保留 700 km 路径、遮挡和资料缺失检查。

**数据约束**：沿用旧版 25% 云量遮挡近似模型；单列原生二维 GFS 云量与气压层数据的既有融合；无新增 API 请求；700 km 或 1.3× 极限云距为已采样验证边界，不推断范围外的天气。若真实太阳方位偏离采样线，只能复用经过位置精度验证的已测离轴剖面，否则该条带标为未确认。

## 案例对照

使用 `2026年11月20日_合肥_GFS(1).zip` 内 `analysis_state.json` 的 17 个压强剖面，关闭二维 OM 横向复核、仅作离线剖面几何对照：原版记录的云底有效染色比例约 0.2%，本版同输入计算在日出前 9 分钟得到云底加权受光条带约 **65.3%**，前缘受光诊断约 **9.8%**。**65.3% 不等于重新联网计算后的正式概率或最终染色占比**：横向 OM 冲突检查、起报一致性和资料缺口仍可能影响最终结果。

## 桌面操作

解压完整包，进入 `V2_2_0`，第一次用 `INSTALL_DESKTOP_DEBUG_DEPENDENCIES.bat` 安装依赖，之后双击 `START_GFS_OM_DESKTOP_DEBUG.bat`。导入旧案例后需选择**缓存重算**才能运行新算法；直接打开之前保存的分析报告不会重写旧结果。建议同时保存新剖面图、诊断 CSV 和生成的案例包。

## 离线测试

当前源代码针对新几何门槛 15 项测试通过（5 项新增，10 项相关原有测试）；项目全套测试 109 通过、20 失败。与本次改动前的完整桌面包比较，旧包为 104 通过、20 失败；20 项仍为旧概览/历史断言及联网环境问题，不能宣称整仓测试全通过。没有执行实时 Open-Meteo 新请求，也没有证明 5 点的云底条带抽样相当于完整二维云底辐射传输模型。
