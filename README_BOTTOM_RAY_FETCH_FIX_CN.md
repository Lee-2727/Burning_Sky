# Burning Sky V2.2.0 — 云底光线补采与验证点对齐修复

## 根因
旧版 `plan_off_axis_rays()` 只为每块云的向阳前缘规划气压层补采，然而 `sky_six.py` 的云底受光验证已经改为沿 0～霞云距、每 15 km 的云底目标位置逐点检查。两者的太阳方向路线并不相同，导致部分已经补采的数据无法覆盖内侧云底目标，出现大量 `unresolved_off_axis`。

## 修改
- 仍然使用固定 15 km 云底受光采样网格（霞云距小于 15 km 时只有一次）；规划气压层补采时使用与实际求解相同的云底目标位置和分钟太阳方向。
- 继续为云锋面规划气压层补采，未删除前缘受光验证。
- 优先复用已查询过的主轴/额外气压层站点；没有覆盖实际光线的坐标才进入新增补采列表，同一坐标去重。
- 从 `(分钟, 云底位置)` 找到对应的真实气压层路线。旧版本只在 `(分钟, 云前缘)` 取数据。
- 地球本身已遮挡的云底光线直接标记，不浪费额外气象请求。
- 保留已知远端云层遮挡、动态上游距离、云量冲突和数据缺失时不得伪造晴空的规则。
- engine.py 原有 20 点/批调用补采接口的流程现在会收到内侧云底点的采样计划；遇到 API 限流/缺测时依旧明确记录未完成，不会把失败的数据填成晴空。

## 验证
- 使用 `2026年11月20日_合肥_GFS(2).zip` 已保存的垂直云场进行补采**规划**，在测试用的 1200 km 范围内，去重后需额外查询约 91 个坐标，规划约 236 条分钟-位置路线（并非每条都单独请求）。这是规划统计，不代表这些气象数据已经实际获取。
- 新增“云底内部目标进入补采计划”“缺失气压层不伪造清空”测试。相关专项 28 项通过。
- 基线总回归 148 通过 / 29 失败；此版 150 通过 / 29 失败，未新增失败。原有 29 项失败未在本补丁中处理。
- **未经 Open-Meteo 联网全流程验证**。遇到 429 或其他真实资料缺失，未完成仍是未完成，而不是无云或零光照。

## 覆盖
从精简补丁里覆盖 `burning_sky/sky_six.py`。两个测试文件仅开发验证使用，不影响程序运行；不必覆盖 `data/`。
完整包保留原有桌面启动器 `START_GFS_OM_DESKTOP_DEBUG.bat`。
